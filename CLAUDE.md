# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

VR boxing simulator for Meta Quest, built in **Unity 6000.4.7f1** (migrated from 2022.3). Active build target is **Android**; XR runs through **OpenXR** with the Meta XR SDK (`com.meta.xr.sdk.all`). The user communicates in Spanish; code comments and README are in Spanish.

## Driving the Editor (Unity CLI + Pipeline)

The project includes `com.unity.pipeline`, so a running Editor can be controlled from the terminal with the `unity` CLI. Prefer this over hand-editing `.unity` / `.prefab` / `.asset` YAML.

```bash
unity status                      # Editor must show state "ready"
unity pipeline list               # shows Pipeline/server reachability and Safe Mode
unity command                     # list command groups; `unity list` lists every command with descriptions
unity command console_status --caller plugin --skill unity-cli --result-only   # compile-failure flag + error/warning counts
unity command console --tail 50 --caller plugin --skill unity-cli --result-only
unity command eval --caller plugin --skill unity-cli --result-only 'return UnityEditor.EditorUserBuildSettings.activeBuildTarget;'
```

- Command parameters are passed as `--name value` (e.g. `add_scene_to_build --path Assets/Scenes/Main_Scene.unity --enabled true`).
- If the Pipeline server is unreachable while the Editor is running, the usual cause is C# compile errors: Unity won't reload the domain, so the Pipeline never loads. Fix the errors from the Editor log (`~/Library/Logs/Unity/Editor.log`, grep `error CS`) first.
- File changes made on disk are only picked up when the Unity window regains focus.

Testing: Play mode in the Editor with the **Meta XR Simulator** works even with Android as the target (Play mode uses the Standalone XR loader settings, which also have OpenXR enabled). Device builds go through *File > Build Profiles > Android > Build And Run*. There are no automated tests. Without a headset, the components' context menus help in Play mode: `ControlCombate` → *Probar: ganar el combate*, `RecuperacionJugador` → *Probar: derribar al jugador*, `PruebaAtaques` → attacks that land, get dodged or get blocked. From the CLI, `capture_game_view` only saves inside the project, so delete the capture afterwards.

## Architecture

- **Scenes:** four scenes, all in Build Settings. `Assets/Scenes/Main_Scene.unity` holds the main menu (a World Space `Canvas`) inside the MarpaStudio boxing arena, with an `OVRCameraRig`, and plays the menu music from a looping `AudioSource` on `MenuMusic`; the boxers standing in it are decoration (Bald Bull and Mr Sandman there are the old `.glb` models). `Scene_Ring_Level1/2/3.unity` are the fights against Glass Joe, Bald Bull and Soda Popinski: same arena, rig and Canvas, no music. Level 2 and 3 are copies of Level 1 with the opponent swapped, so changes to the shared setup (rig, Canvas, pause) must be made in all three.
- **Level flow:** `ControlCombate` (own GameObject in each fight) waits for the `Oponente` to be `Derrotado`, shows a "¡VICTORIA!" panel built in code on the camera, and loads `siguienteEscena` (Level 3 goes back to `Main_Scene`). It stores the highest won level in `PlayerPrefs` `"nivelSuperado"` (nothing reads it yet). Losing is handled by `RecuperacionJugador`, which loads `Main_Scene`.
- **Pause menu:** in the fight scenes, `PauseMenu` (on its own GameObject, not the Canvas, so hiding the Canvas doesn't disable it) toggles the Canvas and laser on `OVRInput.Button.Start` (left controller Menu button, key `M` in the Meta XR Simulator) and sets `Time.timeScale` to 0/1. On opening it moves the Canvas 1.5 m in front of the player's head (the player can walk around the ring) and switches to the main panel. There, the Canvas title reads PAUSA and the buttons are rewired: `ButtonReanudar` → `PauseMenu.Hide`, `ButtonVolverMenu` → `PauseMenu.BackToMainMenu`.
- **Menu input:** VR pointer interaction uses the Meta Core legacy UI stack (`OVRInputModule` + `OVRRaycaster` on the canvas; the input module accepts the right index trigger as well as A, which is what the simulator's Point + Click left mouse button sends). `LaserCursor` derives from `OVRCursor` and draws the ray with a `LineRenderer`, moving a dot to the hit point.
- **`MainMenu`** switches between the main, options and level panels (`MenuNiveles`, only in `Main_Scene`). JUGAR opens the level panel, whose buttons call `PlayLevel(1..3)` (scene names in `MainMenu.Levels`). Options has two 0–1 sliders wired to `SetVolume` and `SetHaptics`, initialised in `Awake` from `PlayerPrefs` `"volumen"` (applied to `AudioListener.volume`) and `"haptica"` (scales the vibration in `Puno` and `SaludJugador`).
- **Hitting opponents:** `Puno` (kinematic, on each hand anchor) measures hand velocity relative to the `TrackingSpace`, so joystick locomotion and snap turns don't count as punches. On `OnTriggerEnter` with a `ZonaGolpe` (trigger hitbox: `Cabeza` or `Torso`), it sends a `Golpe` to the `Oponente`; nothing lands while the player is knocked down. `Oponente` has health (`saludMaxima`): each hit deals the type's base damage, scaled by punch speed and ×`multiplicadorCabeza` on the head. He falls each time health crosses a threshold (with `caidasParaDerrota` = 3: at 66 %, 33 % and 0 %). The falls before the last are knockdowns and he gets up after `segundosKnockdown`; the last one is the defeat (`Derrotado`), and he stays down until `Reiniciar()`. Hits don't count while he is down. `Oponente` raises the events `AlRecibirGolpe`, `AlCaer`, `AlLevantarse` and `AlCambiarSalud`, and these components react to them:
  - `ReaccionAnimada` drives an Animator by state name. For Glass Joe: Jab, Cross and Lateral to the head → `Jab`; Uppercut to the head → `Uppercut_Face`; anything to the torso → `Uppercut_Stomach`; then `Knockdown` / `Defeat`. The controller's exit-time transitions bring the reactions and `Knockdown` back to `Idle`.
  - `ReaccionProcedural` is for the remaining `.glb` characters, which have no skeleton: it leans and pushes the model from the feet with a spring.
  - `AtaqueOponente` makes him turn toward the player (`Camera.main` by default) and attack from `Idle` every `intervaloAtaque` seconds. Every `uppercutCada`-th attack is `Ataque_Uppercut` and the rest are `Ataque_Jab`. Each hit he takes resets the wait to `esperaTrasGolpe`. A reaction started mid-attack cuts the attack off, and he doesn't attack while down or while the player is down. When an attack starts it aims at the player's head; `retardoImpacto*` seconds later (the moment the fist lands in the clip) it calls `SaludJugador.RecibirAtaque` along a line from `alturaAtaque` up to `alcanceAtaque` m.

  Per-character values (name shown to the player, health, damage, timings) live in a `PerfilOponente` asset (`Assets/_Project/Data/Oponentes/`). *Tools > Boxeo > Configurar oponente seleccionado* sets up a character (select the root that holds the Animator, e.g. the FBX/prefab instance). With a Humanoid Animator, it adds `ReaccionAnimada` and builds each hitbox from the vertices skinned to the head and the spine bones, parented to those bones so the hitboxes follow the animation. Without one, it uses heights. It does not add `AtaqueOponente`. Adjust the hitboxes by eye afterwards.
- **Player:** on the `OVRCameraRig`. `SaludJugador` resolves each attack as dodged (head off the punch line), blocked (both hands in guard in front of the face, takes `danoTrasBloqueo`) or hit. At 0 health, `RecuperacionJugador` starts a 10 s count in which mashing A/B/X/Y gets the player up; `saludPorCaida` sets how many times and with how much health, and running out loses by K.O. `FeedbackSalud` is the diegetic feedback (vignette, heartbeat). `LimiteRing` keeps the head inside the ropes and out of the opponent (`distanciaMinima`). `DebugSalud` (health bars, toggled with Y) and `PruebaAtaques` are test-only and the course report asks for no HUD (RF-14).
- **Characters** (`Assets/_Project/Art/Characters/`) are Mixamo rigs. `<Name>.fbx` holds the model, the Humanoid avatar and the idle clip. `Animations/<Name>@<Clip>.fbx` contribute only clips: their avatar is copied from the model, they import no materials, and root motion is baked into the pose, with `applyRootMotion` off. `GlassJoe/Animations/GlassJoe.controller` holds the states (`Idle`, `Jab`, `Uppercut_Face`, `Uppercut_Stomach`, `Knockdown`, `Defeat`, `Ataque_Jab`, `Ataque_Uppercut`). The other characters use an `AnimatorOverrideController` over it: their own clips where they exist and Glass Joe's, retargeted, where they don't (e.g. both use his `Knockdown`, and Soda his `Defeat`). The prefab next to each model (`BaldBull.prefab`, `SodaPopinski.prefab`) has the override assigned.
  - **Glass Joe:** 1.70 m. `Materials/` holds the Standard materials that the FBX remaps by name, each with its texture from `Textures/`. The FBX only references the textures by file name, so new versions are copied over the existing files to keep their `.meta` settings.
  - **Bald Bull** (from the `Richirama` branch): textures embedded in the FBX and extracted to `BaldBull.fbm/`. Scaled 1.15 in Level 2. `Aturdido` is a fall and serves as `Defeat`. `Ataque_Combo` (the uppercut slot) hits several times but only one impact is checked.
  - **Soda Popinski** (from `Richirama`): the model is Mixamo's `Boxing.fbx` export (the original Collada had no rig). Its textures were never committed, so `SodaPopinski.prefab` uses flat placeholder materials from `Materials/` (`Soda_*.mat`, assigned per mesh piece); replace them when the textures turn up. Imported ~2.3 m tall, scaled 0.8 in Level 3. `Golpe_Recibido` is trimmed to the recoil (frames 6–51). `Ataque_Gancho`, `Ataque_Gancho_2` and `Burla` are imported but unused; the hooks walk him forward over a metre.
- **Punch types:** `Golpe.Clasificar` sorts each hit by the hand's direction relative to where the head faces, with a fixed orthodox stance. Mostly upward is `Uppercut`; straight forward is `Jab` with the left hand and `Cross` with the right; anything else is `Lateral` (hooks). Each type has its own base damage in the profile; Lateral gets a soft vibration. Each type has its own vibration pattern in `Puno`, scaled by the `"haptica"` setting. The procedural reaction's `intensidad` saturates at `rapidezGolpeCompleto` (2.5 m/s), so punching harder doesn't add anything. `Oponente` logs every hit to the console (`registrarGolpes`).
- **Gloves:** `Assets/_Project/Art/boxing-gloves/source/Boxing gloves.glb` contains both gloves in one skinned mesh with a squash & stretch rig and animations, none of which are used. *Tools > Boxeo > Poner guantes en las manos* splits the mesh by bone side into the static meshes `Guante_Izquierdo`/`Guante_Derecho.asset` and replaces each `Puno`'s sphere with a `Guante` child. That child is rolled ±90° so the thumb points up while holding a controller. The gloves need glTFast ≥ 6.20: 6.14 fails to import this skinned mesh (`SortAndNormalizeBoneWeightsJob`).
- **Asset layout:** game-owned assets live in `Assets/_Project/` (characters under `Art/Characters/`: one folder per rigged character, the `.glb` ones imported with glTFast; the Bangers TMP font, and audio under `Audio/`; long music clips use the *Streaming* load type). Third-party art lives in `Assets/ThirdParty/MarpaStudio/`, and the scenes use all of it.

## Repository conventions

- Large binaries (png, fbx, wav, zip, dll, …) are tracked with **Git LFS** via `.gitattributes`. On a new machine install Git LFS (`winget install GitHub.GitLFS` on Windows) and run `git lfs install` before cloning, or `git lfs pull` afterwards. Without it the clone contains only text pointers and the arena (textures, meshes) shows up broken or empty; if Unity was already opened, delete `Library/` and reopen.
- Meta Avatars SDK, the multiplayer packages (Netcode, Lobby, Multiplayer Services), Visual Scripting and Timeline were removed on purpose as unused. Don't reintroduce them without a reason. Stale `Oculus.AvatarSDK2*.csproj` files at the root are generated and git-ignored.
- The Meta Project Setup Tool items about the Platform SDK (Data Use Checkup, application ID) don't apply, because the game doesn't use the Platform SDK.
