# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

VR boxing simulator for Meta Quest, built in **Unity 6000.4.7f1** (migrated from 2022.3). Active build target is **Android**; XR runs through **OpenXR** with the Meta XR SDK (`com.meta.xr.sdk.all`). The user communicates in Spanish; code comments and README are in Spanish.

## Driving the Editor (Unity CLI + Pipeline)

The project includes `com.unity.pipeline`, so a running Editor can be controlled from the terminal with the `unity` CLI. Prefer this over hand-editing `.unity` / `.prefab` / `.asset` YAML.

```bash
unity status                      # Editor must show state "ready"
unity pipeline list               # shows Pipeline/server reachability and Safe Mode
unity command                     # list command groups; `unity list` lists every command with descriptions
unity command console_status --caller plugin --skill unity-cli --result-only   # compile-failure flag + error/warning counts
unity command console --tail 50 --caller plugin --skill unity-cli --result-only
unity command eval --caller plugin --skill unity-cli --result-only 'return UnityEditor.EditorUserBuildSettings.activeBuildTarget;'
```

- Command parameters are passed as `--name value` (e.g. `add_scene_to_build --path Assets/Scenes/Main_Scene.unity --enabled true`).
- If the Pipeline server is unreachable while the Editor is running, the usual cause is C# compile errors: Unity won't reload the domain, so the Pipeline never loads. Fix the errors from the Editor log (`~/Library/Logs/Unity/Editor.log`, grep `error CS`) first.
- File changes made on disk are only picked up when the Unity window regains focus.

Testing: Play mode in the Editor with the **Meta XR Simulator** works even with Android as the target (Play mode uses the Standalone XR loader settings, which also have OpenXR enabled). Device builds go through *File > Build Profiles > Android > Build And Run*, or from the CLI with `unity command build --target Android --outputPath Builds/Android/vrboxing_dev.apk --options '["Development"]' --confirm true` (async; poll `build_status`). `Builds/` and `*.apk` are git-ignored. The package is `com.utec.vrhola` (product name "vrhola"); a full Android build takes ~6 min, an incremental one ~2 min, and the development APK is ~200 MB, 94 % of the assets being the arena's 2048 px textures. `docs/Protocolo_Rendimiento.md` is the script for the headset session (install, what to play, `adb pull` of `/sdcard/Android/data/com.utec.vrhola/files/Sesiones`, 30-minute session, empty tables); `python3 Tools/tabla_rendimiento.py <Sesiones folder>` turns the pulled JSON/CSV into the per-level FPS and haptic-latency tables, and `docs/Entrega5.md` (block J) has the per-scene cost audit and the ordered list of possible cuts, none applied yet. There are no automated tests. Without a headset, the components' context menus help in Play mode: `ControlCombate` → *Probar: ganar el combate*, `ControlRondas` → *Probar: acabar el round*, *saltar al round 3*, *ganar por salud*, *perder por salud*, `Arbitro` → *Probar: contar al rival*, *contar al jugador*, `RecuperacionJugador` → *Probar: derribar al jugador*, *pulsar una vez*, `PruebaAtaques` → attacks that land, get dodged or get blocked, `DefensaOponente` → *Probar: subir la guardia*, `EsquiveOponente` → *Probar: esquivar*, `PausaGuardian` → *Probar: salir/volver al área segura*, `MainMenu` → unlock all levels / reset progress, `GrabadoraGuardia` → *Probar: grabar guardia*, `RegistroSesion` (the `DontDestroyOnLoad` object) → *Probar: guardar ahora*, `PantallaResultados` → *Probar: victoria en el nivel 2*, *derrota en el nivel 3*, *campeón (nivel 5)* (made-up data), `CinturonCampeon` → *Probar: desplegar de nuevo*. Results buttons are tested by invoking their `onClick`, which is what `OVRInputModule` does with the laser. From the CLI, `capture_game_view` only saves inside the project, so delete the capture afterwards. Without a headset the head may stay at floor height, so the opponent's attacks fall short and resolve as `Esquivado` (with the Meta XR Simulator running, as in block I, it sat at 1.70 m and the attacks landed): to control it, disable `OVRCameraRig` in Play and place `centerEyeAnchor` and the hand anchors by hand. `OVRCameraRig` rewrites the anchors before each render even while disabled, so to hold them in place set them every frame from an `Application.onBeforeRender` handler added after OVR's (that is how the simulated fights of `docs/Entrega5.md` were run). A Play test that wins a level changes `PlayerPrefs` `"nivelSuperado"`: read it before and restore it after.

## Architecture

- **Scenes:** seven scenes, all in Build Settings. `Assets/Scenes/Main_Scene.unity` holds the main menu (a World Space `Canvas`) inside the MarpaStudio boxing arena, with an `OVRCameraRig`, and plays the menu music from a looping `AudioSource` on `MenuMusic`; the boxers standing in it are decoration (Bald Bull and Mr Sandman there are the old `.glb` models). `Scene_Ring_Level1/2/3/4/5.unity` are the fights against Glass Joe, Bald Bull, Soda Popinski, Mr. Sandman and Iron Mike Tyson: same arena, rig and Canvas, no music. Levels 2 to 5 are copies with the opponent swapped, so changes to the shared setup (rig, Canvas, pause) must be made in all five. `Scene_Results.unity` (build index 6) is a copy of `Main_Scene` without the decoration boxers, `GrabadoraGuardia` or `MainMenu`: the results sheet and the champion belt.
- **Rounds (RF-10, RF-11):** `ControlRondas` (own GameObject in each fight, with a child `Campana` holding the 3D bell source in a ring corner) runs `Preparacion` → `Round` → `Descanso` → ... → `Terminado`: 3 rounds of 90 s, 20 s rest, 5 s before the first bell. One bell strike opens a round and three close it. The clock uses scaled time, so pauses stop it, and it doesn't advance while the player is down. A round that reaches zero waits while `CuentaEnMarcha` (a `Func<bool>` that `Arbitro` sets) returns true. In each rest the opponent gets up, walks back to his start position, drops his guard and can dodge again, and the player regains `fraccionSaludDescanso` of max health; his falls are not reset. Outside rounds `AtaqueOponente` is paused (`Pausar`/`Reanudar`) and `Oponente.Protegido` makes punches not count. A KO ends the fight at once; otherwise the higher health percentage after the last round wins and **a tie goes to the player**. The result is raised in `AlTerminarCombate(ResultadoCombate)`.
- **Referee (RF-12, RF-16):** `Arbitro` (own GameObject in each fight; its child `Cuerpo` holds the body, the 3D `AudioSource` `Voz` at head height and `CartelPulsar`) counts aloud from 1 to 10 with the clips in `numeros` (`Audio/Efectos/Voz_Cuenta_01..10.wav`; overwrite the WAVs or drag other clips to use recordings). For the player it only adds the voice: the time and the mashing stay in `RecuperacionJugador`, and the numbers split `segundosParaLevantarse`. For the rival it runs the count itself in a knockdown (the final fall isn't counted) at `segundosPorNumero`, up to `cuentaKnockdown` from his profile (10 in all three), and then calls `Levantarse`. While `Arbitro` is enabled it sets `Oponente.LevantaArbitro`, which turns off the `segundosKnockdown` timer; without it the rival gets up on that timer. An external `Levantarse` cancels the count and silences the voice. The count stops at `timeScale` 0, and the voice is paused by hand because an `AudioSource` ignores `timeScale`. If both are down (tests only), the player's count has the voice and the rival's keeps running silently. `Arbitro.AlDecirNumero` fires with each number. `CuerpoArbitro` (on `Cuerpo`) moves the visible referee: during the round 2 m to the side of the player–rival line, for the rival's count next to the rival on the player's side, for the player's count 1.05 m ahead of the player and 0.4 m aside (it picks the side that stays inside the ring), and back to its start spot outside rounds; never closer than 0.6 m to either fighter, clamped with `LimiteRing.DentroDelRing`. It glides (no walk clip), raises the counting arm during a count and chops it down with each number, and shows the world-space sign "¡ARRIBA! PULSA A B X Y" only during the player's count. `Cuerpo > Modelo` is `Art/Characters/Referee/Referee.fbx` (Humanoid, no colliders) with `Animations/Referee.controller`: a 1D blend tree on the float `Agachado` between `Referee_DePie.anim` (0, a standing pose generated in muscle space from the FBX's `TPose`, breathing) and the FBX's crouched `Pose_Referee` (1); `CuerpoArbitro` drives it to 0.55 in rounds, 0.3 in the rival's count and 0 otherwise. With a humanoid `Animator` and `brazoCuenta` empty, the counting gesture rotates the avatar's right upper arm and forearm in `LateUpdate`, over the animation, blended in by weight; `brazoCuenta` (rotates on local X) is only for skeleton-less models. `Contar`/`Contando`/`Agachado` are sent only if the controller has them. *Tools > Boxeo > Montar réferi* creates the pose and controller if missing and mounts (or swaps) the model in the open scene. The FBX in use is decimated from ~379k to 20k triangles by `Tools/reducir_referi.py` (Blender, decimate before the armature modifier, keeps weights/UV); the untouched original is in `Referee/Source~/` (not imported). Its two clips are single-frame takes, so `clipAnimations` sets the take's frame range explicitly (the default 0–0 imports empty clips).
- **Level flow:** `ControlCombate` (own GameObject in each fight) listens to `ControlRondas` (without one in the scene, it wins when the `Oponente` is `Derrotado`), shows a "¡VICTORIA!" panel built in code on the camera, and loads `escenaResultados` (`Scene_Results`); only if that field is empty does it load `siguienteEscena` directly (Level 5's panel says "¡Eres el nuevo campeón!"). It stores the highest won level in `PlayerPrefs` `"nivelSuperado"`, which `MainMenu` reads to unlock levels (RF-09): level N opens once N-1 is won, and locked buttons show BLOQUEADO and don't load. `MainMenu`'s context menu can unlock everything or reset progress. Losing is handled by `RecuperacionJugador`, which after the K.O. or, through `PerderPorSalud`, the DERROTA sign loads its own `escenaResultados` (`Scene_Results`; `escenaAlPerder` is the fallback). The new fields take their defaults in the five fight scenes without re-saving them.
- **Results (RF-18, RF-19):** `PantallaResultados` (own GameObject in `Scene_Results`) gets nothing passed in: it reads `RegistroSesion.Instancia.CombateActual`, which was closed before the scene change and survives it, and shows title (¡VICTORIA!, DERROTA or ¡CAMPEÓN!), how the fight ended, precision (`precision`, landed of thrown), blocked attacks (`ataquesBloqueados` of `ataquesRecibidos`), total time (`segundosCombate`) and a detail line, on the menu's World Space Canvas (`OVRRaycaster`, `OVRInputModule`, `LaserCursor`, Bangers). Main button: SIGUIENTE NIVEL (`MainMenu.Levels[nivel]`) after winning levels 1–4, REINTENTAR (the fight's scene) after losing, REPETIR after winning level 5; the other is MENÚ (centred alone when there is no fight). A win plays `Multitud_Ovacion.wav` once. Winning the last level activates the belt, moves the Canvas 0.45 m right, turns it 15° and scales it to 80 %, and the subtitle becomes the closing text `textoCampeon`. The belt (`Art/CinturonCampeon/`) is the team's own, built by `Tools/crear_cinturon.py` (Blender headless; 1 540 triangles, no UVs or textures, three Standard materials remapped by name, axis conversion baked into the mesh): `CinturonCampeon` rises 0.6 m growing from 20 % with a small overshoot, spins at 35 °/s and pulses the gold's emission through a `MaterialPropertyBlock` (`Cinturon_Oro` keeps `_EMISSION` on with black emission for that), in unscaled time and with no light of its own.
- **Pause menu:** in the fight scenes, `PauseMenu` (on its own GameObject, not the Canvas, so hiding the Canvas doesn't disable it) toggles the Canvas and laser on `OVRInput.Button.Start` (left controller Menu button, key `M` in the Meta XR Simulator) and sets `Time.timeScale` to 0/1. On opening it moves the Canvas 1.5 m in front of the player's head (the player can walk around the ring) and switches to the main panel. There, the Canvas title reads PAUSA and the buttons are rewired: `ButtonReanudar` → `PauseMenu.Hide`, `ButtonVolverMenu` → `PauseMenu.BackToMainMenu`. `PauseMenu.Show(string)` opens it with another title. `PausaGuardian` (next to `PauseMenu`, RF-20) pauses when the head leaves the Guardian's Play Area (`OVRBoundary.GetGeometry`, tracking space) or the app loses input focus / the headset is removed, shows "VUELVE AL ÁREA SEGURA", and resumes only the pauses it opened. The Editor has no Guardian: use its context menus (*Probar: salir/volver al área segura*) or `simularAreaEnEditor`.
- **Menu input:** VR pointer interaction uses the Meta Core legacy UI stack (`OVRInputModule` + `OVRRaycaster` on the canvas; the input module accepts the right index trigger as well as A, which is what the simulator's Point + Click left mouse button sends). `LaserCursor` derives from `OVRCursor` and draws the ray with a `LineRenderer`, moving a dot to the hit point.
- **`MainMenu`** switches between the main, options and level panels (`MenuNiveles`, only in `Main_Scene`). JUGAR opens the level panel, whose buttons call `PlayLevel(1..5)` (scene names in `MainMenu.Levels`); the first four sit in a row and `ButtonNivel5` alone in a second row below them. Options has two 0–1 sliders wired to `SetVolume` and `SetHaptics`, initialised in `Awake` from `PlayerPrefs` `"volumen"` (applied to `AudioListener.volume`) and `"haptica"` (scales the vibration in `Puno` and `SaludJugador`).
- **Physics** runs at 72 Hz: *Fixed Timestep* is exactly 1/72 s (one step per Quest 2 frame, so an impact is detected at most one frame late; it was 0.02 s until block J). Only `Puno` uses `FixedUpdate`.
- **Hitting opponents:** `Puno` (kinematic, on each hand anchor) measures hand velocity relative to the `TrackingSpace`, so joystick locomotion and snap turns don't count as punches. Its smoothing `suavizado` is defined per 0.02 s and scaled to the real step, so the filter keeps the time constant it was calibrated with at 50 Hz. On `OnTriggerEnter` with a `ZonaGolpe` (trigger hitbox: `Cabeza` or `Torso`), it sends a `Golpe` to the `Oponente`; nothing lands while the player is knocked down. `Oponente` has health (`saludMaxima`): each hit deals the type's base damage, scaled by punch speed and ×`multiplicadorCabeza` on the head. He falls each time health crosses a threshold (with `caidasParaDerrota` = 3: at 66 %, 33 % and 0 %). The falls before the last are knockdowns and he gets up when `Arbitro` ends the count (`segundosKnockdown` without a referee), protected from hits for `segundosAlLevantarse` while the clip gets him up; the last one is the defeat (`Derrotado`), and he stays down until `Reiniciar()`. Hits don't count while he is down. `RecibirGolpe` returns a `ResultadoGolpe` (`NoCuenta`, `Conectado`, `Bloqueado`, `Esquivado`). `Oponente` raises the events `AlRecibirGolpe`, `AlBloquear`, `AlEsquivar`, `AlCaer`, `AlLevantarse` and `AlCambiarSalud`, and these components react to them:
  - `DefensaOponente` (RF-07) decides which punches he blocks: the profile's `probabilidadBloqueo`, rising by `bloqueoPorGolpeSeguido` per consecutive hit up to `bloqueoMaximo`. A block keeps the guard up for `segundosGuardia` (blocks everything, punching more doesn't extend it), then he is open for `aberturaTrasGuardia` and can't block. He never blocks while attacking. A blocked punch deals ×`danoTrasBloqueo`, never knocks him down and fires `AlBloquear` instead of `AlRecibirGolpe` (no reaction animation). The guard is shown with hand IK (Humanoid only): `DefensaOponente` adds a `RelevoIK` to the Animator object because `OnAnimatorIK` only reaches that object, and the base layer of `GlassJoe.controller` has IK Pass on (the override controllers inherit it). With `PerfilOponente.guardiaGrabada` set, the gloves follow that recorded trajectory (forward when raising, backward when lowering), starting from the animated hand pose (`GetIKPosition` at weight 0) and blending that offset out along the way, scaled by the rival's head height over the recorder's; without it they go straight to the fixed `posicionGuantes`. Recordings (`GrabacionGuardia` assets in `Data/Guardias/`) come from `GrabadoraGuardia` on the `OVRCameraRig` of `Main_Scene`: both thumbsticks pressed (or its context menu) → haptic countdown, 2 s of both hands relative to the head's yaw-only frame, trimmed to the raise, saved as JSON in `persistentDataPath/Guardias` and, in the Editor, as an asset. *Tools > Boxeo > Importar guardias grabadas* imports JSON pulled from the Quest. All four profiles use `Guardia_Provisional` (synthesized without a headset, *Tools > Boxeo > Crear guardia provisional*) until a real one is recorded. Hand rotations are recorded but not applied yet. Without a headset `OVRCameraRig` rewrites the hand anchors before rendering even when disabled, so the recorder accepts its own head/hand/floor transforms for tests.
  - `EsquiveOponente` (RF-07) decides at contact, before the block, so a feint doesn't trigger it: `probabilidadEsquive` (0 = never, the default), then `enfriamientoEsquive`. It doesn't dodge while attacking, down, getting up, `Protegido`, or with the guard up or just dropped (`DefensaOponente.GuardiaOcupada`). A dodged punch deals no damage, isn't a consecutive hit for `DefensaOponente`, gives no impact vibration and fires `AlEsquivar`, to which `AtaqueOponente` answers with `ventanaContraataque`. With no dodge clip yet it moves the transform by `distanciaEsquive`, away from the glove or backward, and comes back: the offset is applied as a per-frame delta, so it adds to `Acercarse` (which waits for it) and the walk home in the rest, and leaves no drift. Hitboxes follow because they hang from the bones, and `LimiteRing.DentroDelRing` keeps him inside the ropes.
  - `ReaccionAnimada` drives an Animator by state name. For Glass Joe: Jab, Cross and Lateral to the head → `Jab`; Uppercut to the head → `Uppercut_Face`; anything to the torso → `Uppercut_Stomach`; then `Knockdown` / `Defeat`. The controller's exit-time transitions bring the reactions and `Knockdown` back to `Idle`. The `Knockdown` clip falls, stays down and gets up in 3.7 s, so with a referee `ReaccionAnimada` holds it at `momentoPiso` until the count ends and then lets it continue.
  - `ReaccionProcedural` is for the remaining `.glb` characters, which have no skeleton: it leans and pushes the model from the feet with a spring.
  - `AtaqueOponente` makes him turn toward the player (`Camera.main` by default) and attack from `Idle` every `intervaloAtaque` seconds. With an empty `combo` in the profile, every `uppercutCada`-th attack is `Ataque_Uppercut` and the rest are `Ataque_Jab`. With a `combo` (a `TipoAtaque[]`), each attack chains those punches without going through `Idle`, starting the next one `segundosEntreGolpesCombo` after each impact; each punch aims at the head again. A connected hit, a fall, the player going down, `Pausar` or disabling the component cancel the rest of the combo and any pending impact; a punch the player blocks doesn't. `Atacando` stays true between combo punches, so he neither blocks nor dodges there. Each hit he takes resets the wait to `esperaTrasGolpe`. A reaction started mid-attack cuts the attack off, and he doesn't attack while down or while the player is down. Nor does he launch while the player's head is farther than `alcanceAtaque` from `alturaAtaque` (the impact geometry): he keeps walking in and attacks as soon as he arrives. When an attack starts it aims at the player's head; `retardoImpacto*` seconds later (the moment the fist lands in the clip, divided by `velocidadAtaque`, which also sets `Animator.speed` during the attack) it calls `SaludJugador.RecibirAtaque` along a line from `alturaAtaque` up to `alcanceAtaque` m. Reactive behaviour: from `Idle` he walks toward the player at `velocidadDesplazamiento` until `distanciaCombate`, clamped to `LimiteRing.AreaRing`; while the player's guard is down (`SaludJugador.EnGuardia`) the wait runs ×(1 + `castigoGuardiaBaja`) faster; after a block he counterattacks after `contraataqueTrasBloqueo`.

  Per-character values (name shown to the player, health, damage, defence, speed, timings, sounds) live in a `PerfilOponente` asset (difficulty rises Glass Joe < Bald Bull < Soda Popinski < Mr. Sandman < Iron Mike Tyson, RF-08; `python3 Tools/modelo_dificultad.py` estimates each rival's damage per second and the punches needed to beat him, and `docs/Entrega5.md` explains the simulated fight used to compare them) (`Assets/_Project/Data/Oponentes/`). *Tools > Boxeo > Configurar oponente seleccionado* sets up a character (select the root that holds the Animator, e.g. the FBX/prefab instance). With a Humanoid Animator, it adds `ReaccionAnimada` and `DefensaOponente` (turning on IK Pass in the base controller) and builds each hitbox from the vertices skinned to the head and the spine bones, parented to those bones so the hitboxes follow the animation. Without one, it uses heights. It also adds `EsquiveOponente`, inert while the profile's probability is 0. It does not add `AtaqueOponente`. Adjust the hitboxes by eye afterwards.
- **Player:** on the `OVRCameraRig`. `SaludJugador` resolves each attack as dodged (head off the punch line), blocked (both hands in guard in front of the face, takes `danoTrasBloqueo`) or hit. At 0 health, `RecuperacionJugador` starts a 10 s count in which mashing A/B/X/Y gets the player up; `saludPorCaida` sets how many times and with how much health, and running out loses by K.O. The count has no panel: `Arbitro` says it, and only the final K.O. and DERROTA signs are shown on the camera. `FeedbackSalud` is the diegetic feedback (vignette, heartbeat; the clip must be a single short beat, `Audio/Efectos/Latido.wav`). During the count it follows `Progreso` instead of health: the view clears and the heartbeat calms with each press, and each press vibrates harder (`AlPulsar`). Hits taken and blocked sound in 3D at the impact point (`SaludJugador` sound fields). `LimiteRing` keeps the head inside the ropes and out of the opponent (`distanciaMinima`). `DebugSalud` (health bars, hidden at start, toggled with Y) and `PruebaAtaques` are test-only and the course report asks for no HUD (RF-14).
- **Session log (RF-21):** `RegistroSesion` creates itself at startup (`RuntimeInitializeOnLoadMethod`, `DontDestroyOnLoad`), so no scene holds it. In each scene with an `Oponente` it listens to existing events (no gameplay changes) and records per fight: level, rival, retry, result (or `Abandonado` when the scene is left early), round, fight seconds, punches thrown (`Puno.AlLanzarGolpe`: hand moving away from the head faster than 1.5 m/s, or touching the rival), landed by type, blocked and dodged by the rival, precision and effectiveness, attacks received/blocked/dodged, falls, counts survived, final health, vibrations and FPS during rounds, and the haptic latency (RNF-02): mean, p95 and max of the code latency (from `Puno.OnTriggerEnter`, which stamps `Haptica.Ahora()`, to the return of `OVRInput.SetControllerVibration`, published by `Haptica.AlMedirLatencia` for the first pulse of each punch's pattern) and of the estimated detection delay (`Puno.AlEstimarRetrasoDeteccion`: penetration depth into the hitbox over entry speed, i.e. what the physics step lost), plus `pasoFisicaMs`. The runtime/controller part of the latency can't be measured from code. New fields and CSV columns always go at the end; an older `combates.csv` only gets its header line extended. It writes `persistentDataPath/Sesiones/sesion_<id>.json` (rewritten after each fight, on scene exit, pause and quit) and appends to `combates.csv`. `ControlCombate.Nivel` exposes the level. `CombateActual` keeps the last (closed) fight until another starts, which is what `Scene_Results` shows. Examples in `docs/ejemplos/`.
- **Audio (RF-16):** `Assets/_Project/Audio/Efectos/` holds punches, block, hit taken, heartbeat, crowd, bell and the referee's numbers (a formant synthesizer), synthesized by `Tools/sintetizar_audio.py` (stdlib-only Python, fixed seeds; run `python3 Tools/sintetizar_audio.py Assets/_Project/Audio/Efectos` to regenerate; this also overwrites recordings placed over the `Voz_Cuenta` clips). `AmbienteMultitud` (object `Multitud` at the ring centre in each fight) loops the murmur from several 3D sources around the ring and cheers from the nearest ones when the opponent or the player falls. The opponent's `AudioSource` and the referee's voice are 3D.
- **Characters** (`Assets/_Project/Art/Characters/`) are Mixamo rigs, except Mr. Sandman, Iron Mike Tyson (Mixamo bone names, rigged by the team) and the referee. `<Name>.fbx` holds the model, the Humanoid avatar and the idle clip. `Animations/<Name>@<Clip>.fbx` contribute only clips: their avatar is copied from the model, they import no materials, and root motion is baked into the pose, with `applyRootMotion` off. `GlassJoe/Animations/GlassJoe.controller` holds the states (`Idle`, `Jab`, `Uppercut_Face`, `Uppercut_Stomach`, `Knockdown`, `Defeat`, `Ataque_Jab`, `Ataque_Uppercut`, `Ataque_Gancho`, `Ataque_Gancho_2`). A new attack state must also go in `AtaqueOponente.EsAtaque`. The other characters use an `AnimatorOverrideController` over it: their own clips where they exist and Glass Joe's, retargeted, where they don't (e.g. both use his `Knockdown`, and Soda his `Defeat`). Overrides replace clips, not states, so each state needs its own base clip: the hook states use Soda's clips directly and need no override. The prefab next to each model (`BaldBull.prefab`, `SodaPopinski.prefab`) has the override assigned.
  - **Glass Joe:** 1.70 m. `Materials/` holds the Standard materials that the FBX remaps by name, each with its texture from `Textures/`. The FBX only references the textures by file name, so new versions are copied over the existing files to keep their `.meta` settings.
  - **Bald Bull** (from the `Richirama` branch): textures embedded in the FBX and extracted to `BaldBull.fbm/`. Scaled 1.15 in Level 2. `Aturdido` is a fall and serves as `Defeat`. `Ataque_Combo` (the uppercut slot) hits several times but only one impact is checked.
  - **Soda Popinski** (from `Richirama`): the model is Mixamo's `Boxing.fbx` export (the original Collada had no rig). Its textures were never committed, so `SodaPopinski.prefab` uses flat placeholder materials from `Materials/` (`Soda_*.mat`, assigned per mesh piece); replace them when the textures turn up. Imported ~2.3 m tall, scaled 0.8 in Level 3. `Golpe_Recibido` is trimmed to the recoil (frames 6–51). `Ataque_Gancho` and `Ataque_Gancho_2` are his attacks through `combo`; they walked him forward 1.33 and 0.71 m, so unlike the other clips their XZ root motion is **not** baked into the pose, and with `applyRootMotion` off the body stays in place. `Ataque_Gancho` also holds a second punch that doesn't count, so a combo shouldn't end on it. `Burla` is imported but unused.
  - **Mr. Sandman** (Level 4): not a Mixamo rig. `MrSandman.fbx` is exported from the team's `Source~/mr_sandman_tpose_rig.blend` (21 bones named `Hips`, `UpperArm.L`, ..., T-pose, 1.88 m) by `Tools/exportar_sandman.py` (Blender, headless): it drops the cube, camera and light, joins the 22 pieces into one skinned mesh (~14k triangles, 22 materials), writes the packed textures to `Textures/Sandman_<piece>.png` and exports in metres without leaf bones. The importer maps `Chest` and the toes by hand (auto-mapping skipped them, and the torso hitbox hangs from `Chest`). He uses Soda's override controller and clips (no clips of his own), scale 1, with `PerfilOponente` `MrSandman.asset`; the clips are the same, so the `retardoImpacto*` values still hold. In Level 4 the root `MrSandman` keeps all its components and references; only its children (model), avatar and hitboxes were swapped. **`ApoyoEnSuelo`** (on the Animator object): the humanoid retarget places the body by its centre of mass and doesn't know about his 22 cm of boot below the ankle, so Soda's clips sank the boots into the canvas; after the animation it lifts the hips by however far the soles sank (sole points computed in the Editor with its context menu *Calcular suelas* and serialized, so the mesh needs no Read/Write). It never pulls down and does nothing when the soles aren't below the floor (e.g. lying in `Knockdown`). `MrSandman.prefab` has the override and `ApoyoEnSuelo`. The old `mr_sandman.glb` (no skeleton) is only the decoration in `Main_Scene`.
  - **Iron Mike Tyson** (Level 5): rigged by the team (`Source~/mike_rig.blend`, exported as `Source~/export/mike_rigged_1.78m_v1.fbx`, 1.78 m, T-pose) with Mixamo bone names, so the Humanoid avatar maps itself (no fingers). `Tools/reducir_tyson.py` (Blender, headless) builds `MikeTyson.fbx` from it: it moves to the nearest bone the forearm weight of any vertex more than 15 cm from the forearm (the rig tied the top of each shoulder to the forearm, which stuck out like a blade in the guard), decimates from ~31k to 15k triangles before the armature modifier, writes the embedded texture to `Textures/MikeTyson_BaseColor.jpg` and exports without it (`Materials/MikeTyson.mat`, Standard, remapped by name). Like Sandman he uses Soda's override controller and clips at scale 1 (the `retardoImpacto*` values were re-measured on his body and still hold), and `MikeTyson.prefab` has the override and `ApoyoEnSuelo` (Soda's clips sank his soles 6–14 cm). His profile `MikeTyson.asset` is the hardest: 250 health, ×1.5, a four-punch combo `Gancho2, Gancho, Uppercut, Gancho2` every 2–3 s, 30→65 % block and 50 % dodge. In Level 5 the root `MikeTyson` is Level 4's root with its components and references kept; only its children (model), avatar, profile, soles and hitboxes were swapped.
- **Punch types:** `Golpe.Clasificar` sorts each hit by the hand's direction relative to where the head faces, with a fixed orthodox stance. Mostly upward is `Uppercut`; straight forward is `Jab` with the left hand and `Cross` with the right; anything else is `Lateral` (hooks). Each type has its own base damage in the profile; Lateral gets a soft vibration. Each type has its own vibration pattern in `Puno`, scaled by the `"haptica"` setting; a punch the opponent blocks gets a dull low-frequency double tap (RF-15), one he dodges a faint 30 ms brush, and one that knocks him down three strong pulses. During the player's count `FeedbackSalud` adds a tick per number on both controllers (0.2 → 0.6). All combat vibration goes through the static `Haptica` (`Fijar`/`Apagar`), which raises `AlVibrar` so tests and the session log can observe it; only `MainMenu`'s slider preview calls `OVRInput` directly. The procedural reaction's `intensidad` saturates at `rapidezGolpeCompleto` (2.5 m/s), so punching harder doesn't add anything. `Oponente` logs every hit to the console (`registrarGolpes`).
- **Gloves:** `Assets/_Project/Art/boxing-gloves/source/Boxing gloves.glb` contains both gloves in one skinned mesh with a squash & stretch rig and animations, none of which are used. *Tools > Boxeo > Poner guantes en las manos* splits the mesh by bone side into the static meshes `Guante_Izquierdo`/`Guante_Derecho.asset` and replaces each `Puno`'s sphere with a `Guante` child. That child is rolled ±90° so the thumb points up while holding a controller. The gloves need glTFast ≥ 6.20: 6.14 fails to import this skinned mesh (`SortAndNormalizeBoneWeightsJob`).
- **Asset layout:** game-owned assets live in `Assets/_Project/` (characters under `Art/Characters/`: one folder per rigged character, the `.glb` ones imported with glTFast; source files (`.blend`, originals, modelling screenshots) go in a `Source~` subfolder, which Unity doesn't import: `Referee/Source~`, `MrSandman/Source~` and `MikeTyson/Source~`, the latter holding the sources of `MikeTyson.fbx` (`export/mike_rigged_1.78m_v1.fbx`); props under `Art/` too, such as `Art/CinturonCampeon/` with its generated `.blend` in `Source~`; the Bangers TMP font, and audio under `Audio/`; long music clips use the *Streaming* load type). Third-party art lives in `Assets/ThirdParty/MarpaStudio/`, and the scenes use all of it.

## Repository conventions

- Large binaries (png, fbx, wav, zip, dll, …) are tracked with **Git LFS** via `.gitattributes`. On a new machine install Git LFS (`winget install GitHub.GitLFS` on Windows) and run `git lfs install` before cloning, or `git lfs pull` afterwards. Without it the clone contains only text pointers and the arena (textures, meshes) shows up broken or empty; if Unity was already opened, delete `Library/` and reopen.
- Meta Avatars SDK, the multiplayer packages (Netcode, Lobby, Multiplayer Services), Visual Scripting and Timeline were removed on purpose as unused. Don't reintroduce them without a reason. Stale `Oculus.AvatarSDK2*.csproj` files at the root are generated and git-ignored.
- The Meta Project Setup Tool items about the Platform SDK (Data Use Checkup, application ID) don't apply, because the game doesn't use the Platform SDK.
