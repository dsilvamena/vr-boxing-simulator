# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

VR boxing simulator for Meta Quest, built in **Unity 6000.4.7f1** (migrated from 2022.3). Active build target is **Android**; XR runs through **OpenXR** with the Meta XR SDK (`com.meta.xr.sdk.all`). Only **Quest 2** is declared (`supportedDevices` = `quest2`, decided: Quest 3 is not declared; for RNF-09 it is enough to note whether the APK runs on a Quest 3). Android uses the *Medium* quality level (index 2), with **4× MSAA** (to be confirmed with the headset FPS) and, since the only shadow-casting light is the one over the ring, shadow distance 12 m at *Medium* resolution (the Editor's *Ultra* level has shadow distance 20 m; the other levels are untouched). The user communicates in Spanish; code comments and README are in Spanish.

## Driving the Editor (Unity CLI + Pipeline)

The project includes `com.unity.pipeline`, so a running Editor can be controlled from the terminal with the `unity` CLI. Prefer this over hand-editing `.unity` / `.prefab` / `.asset` YAML.

```bash
unity status                      # Editor must show state "ready"
unity pipeline list               # shows Pipeline/server reachability and Safe Mode
unity command                     # list command groups; `unity list` lists every command with descriptions
unity command console_status --caller plugin --skill unity-cli --result-only   # compile-failure flag + error/warning counts
unity command console --tail 50 --caller plugin --skill unity-cli --result-only
unity command eval --caller plugin --skill unity-cli --result-only 'return UnityEditor.EditorUserBuildSettings.activeBuildTarget;'
```

- Command parameters are passed as `--name value` (e.g. `add_scene_to_build --path Assets/Scenes/Main_Scene.unity --enabled true`).
- If the Pipeline server is unreachable while the Editor is running, the usual cause is C# compile errors: Unity won't reload the domain, so the Pipeline never loads. Fix the errors from the Editor log (`~/Library/Logs/Unity/Editor.log`, grep `error CS`) first.
- File changes made on disk are only picked up when the Unity window regains focus.

Testing: Play mode in the Editor with the **Meta XR Simulator** works even with Android as the target (Play mode uses the Standalone XR loader settings, which also have OpenXR enabled). Device builds go through *File > Build Profiles > Android > Build And Run*, or from the CLI with `unity command build --target Android --outputPath Builds/Android/vrboxing_dev.apk --options '["Development"]' --confirm true` (async; poll `build_status`). `Builds/` and `*.apk` are git-ignored. The package is `com.utec.vrhola` (don't change it: the Quest data folder and PlayerPrefs depend on it); the visible name (`productName`) is "Simulador de Boxeo RV", the report's cover title shortened (it was "vrhola" until 2026-11-11). In the macOS Editor `productName` decides where PlayerPrefs and `persistentDataPath` live (`~/Library/Application Support/utec/Simulador de Boxeo RV`); Editor sessions and guards recorded before the rename are still in `.../utec/vrhola`. A full Android build takes 2–6 min (6 with a cold IL2CPP cache), an incremental one ~2 min; the development APK is 198.0 MB (193.6 MB on its first build of that day, the same as before the pass; the rest is holes from incremental packaging) and the release one 169.1 MB (both rebuilt on 2026-11-14 from commit `f4d04eb`, with the second polish pass, branch `entrega-final/pulido-combate`, with incremental builds; `vrboxing_dev_sinmsaa.apk`, the development APK with *Medium*'s MSAA at 0, built by setting `antiAliasing` = 0 only for that build and restoring 4, is still the one of 2026-11-13, commit `e76dc0f`), 94 % of the packed assets being the arena's 2048 px textures. An incremental build can leave several MB of holes inside the APK (Gradle's incremental packaging doesn't compact the zip), so to measure the size build with `CleanBuildCache`. `docs/Protocolo_Rendimiento.md` is the script for the headset session (install, what to play, `adb pull` of `/sdcard/Android/data/com.utec.vrhola/files/Sesiones`, 30-minute session, empty tables); `python3 Tools/tabla_rendimiento.py <Sesiones folder>` turns the pulled JSON/CSV into the per-level FPS and haptic-latency tables, and `docs/Entrega5.md` (block J) has the per-scene cost audit and the ordered list of possible cuts, none applied yet. *Tools > Boxeo > Rendimiento* applies and undoes cuts 1–3 with one click (no shadows on non-directional lights in the 7 scenes, which since the arena dressing of 2026-11-14 finds nothing left to change; Mipmap Limit 1 in *Medium*; the `FoveacionFija` component, in no scene by default, added to the `OVRManager` object): each writes the previous values to `ProjectSettings/RecortesRendimiento.json` and *Deshacer* restores them exactly, deleting the file when nothing is applied (apply + undo leaves `git diff` empty). The user-test session follows `docs/Protocolo_HEART.md` (5–8 novices, codes P01..., no names; instruments and CSV templates in `docs/heart/`), and `python3 Tools/tabla_heart.py <Sesiones> --observacion obs.csv --cuestionario resp.csv` crosses sessions, observation sheet and questionnaire per participant into the HEART table and the RNF-03/RNF-05 verdicts. `datos_visor/` and `datos_heart/` (pulled data) are git-ignored. There are no automated tests. Without a headset, the components' context menus help in Play mode: `ControlCombate` → *Probar: ganar el combate*, `ControlRondas` → *Probar: acabar el round*, *saltar al round 3*, *ganar por salud*, *perder por salud*, `Arbitro` → *Probar: contar al rival*, *contar al jugador*, `RecuperacionJugador` → *Probar: derribar al jugador*, *pulsar una vez*, `PruebaAtaques` → attacks that land, get dodged or get blocked, `DefensaOponente` → *Probar: subir la guardia*, `EsquiveOponente` → *Probar: esquivar*, `PausaGuardian` → *Probar: salir/volver al área segura*, `MainMenu` → unlock all levels / reset progress, `GrabadoraGuardia` → *Probar: grabar guardia*, `RegistroSesion` (the `DontDestroyOnLoad` object) → *Probar: guardar ahora*, `PantallaResultados` → *Probar: victoria en el nivel 2*, *derrota en el nivel 3*, *campeón (nivel 5)* (made-up data), `CinturonCampeon` → *Probar: desplegar de nuevo*, `CuerpoVivo` → *Probar: gancho a la cabeza*, *recto a la cabeza*. From the CLI, `capture_game_view` only saves inside the project, so delete the capture afterwards. A Play test that wins a level changes `PlayerPrefs` `"nivelSuperado"`: read it before and restore it after.

## Architecture

- **Scenes:** seven scenes, all in Build Settings. `Assets/Scenes/Main_Scene.unity` holds the main menu (a World Space `Canvas`) inside the MarpaStudio boxing arena, with an `OVRCameraRig`, and plays the menu music from a looping `AudioSource` on `MenuMusic`; the five rivals standing in it, in level order from left to right, are decoration: the rigged prefabs of the fights with only `CuerpoVivo` (they breathe and look at the player), placed by *Tools > Boxeo > Poner rivales en el menú* (the old `bald_bull.glb` and `mr_sandman.glb` are no longer used by any scene). Glass Joe and Soda keep their own `Idle`; Bald Bull (pounding his gloves), Mr. Sandman (gloves on hips) and Tyson (weaving in his peek-a-boo guard) play a generated looping pose (`Art/Characters/Menu/Menu_<Name>.anim`, each in a one-state controller whose state is named `Idle`). The tool also leaves the five skeletons at the first frame of their pose inside the saved scene, and *Tools > Boxeo > Posar rivales en las peleas* does the same for the rival of each fight, so nobody shows up in T-pose outside Play (bone overrides in the scene files; in Play the Animator rewrites them every frame). `Scene_Ring_Level1/2/3/4/5.unity` are the fights against Glass Joe, Bald Bull, Soda Popinski, Mr. Sandman and Iron Mike Tyson: same arena, rig and Canvas, no music. Levels 2 to 5 are copies with the opponent swapped, so changes to the shared setup (rig, Canvas, pause) must be made in all five. `Scene_Results.unity` (build index 6) is a copy of `Main_Scene` without the decoration boxers, `GrabadoraGuardia` or `MainMenu`: the results sheet and the champion belt.
- **Arena dressing (all seven scenes, *Tools > Boxeo > Vestir arena*, `ArenaBuilder`; re-runnable, third-party assets untouched, own ones in `Art/Arena/`):** the building (everything under `Building` except the ring pieces `RingFloor`, `Rope`, `Corner`, `Hook`, `RingPillarsBase`, `Banner`, `Stairs`) is on the user layer **`Arena`** (6). The former sun-like directional light is now `LuzRing`: near-vertical, warm, the only per-pixel and shadow-casting light, with `Arena` excluded from its culling mask, so the building is neither lit by it nor rendered into its shadow map (before, the roof shadowed the whole scene and >1 000 objects went into the shadow map). The building's spots are cool, dim, `ForceVertex`, no shadows; the centre point light is off; `LucesRing` holds four vertex point lights at the ring corners (warm on the player's side, blue behind the rival); ambient is Trilight (warm ground colour as canvas bounce) with dark exponential-squared fog. `RingVestido/Lona` is a quad 4 mm above the ring floor with a 1024 px texture painted by the tool (text sampled from the Bangers SDF atlas); corners are red (rival, +X +Z), blue (player, −X −Z) and two white neutral ones; ropes red/white/blue and, like the hooks, cast no shadow. `Publico` (`PublicoBuilder`) is one 1 866-triangle mesh of 834 spectator cards and 99 camera flashes on the arena's `PlaneSeat` quads, drawn by the unlit cutout shader `Boxeo/Publico` (tint and animation phase in the vertex colour; it sways them, and the global `_PublicoAnimo`, set by `AmbienteMultitud` on a cheer, makes them jump and flash); disable the object to remove the crowd. The shader carries the stereo-instancing macros but has only been seen in the simulator's MultiPass.
- **`Maniqui` (Editor):** builds humanoid clips in code. A hidden copy of a character is posed (sample a clip or `PoseDePie`, then root-space bone rotations and analytic two-bone IK for arms and legs; `MoverCadera` re-plants the feet), `HumanPoseHandler` captures the pose as muscles, and `EscribirClip` writes the captures as keyframes (rewrites an existing `.anim` in place, keeping its GUID). Distances are given in shoulder widths (`Ancho`). Used by `MenuBuilder` (menu poses) and `ReaccionesBuilder` (*Tools > Boxeo > Crear reacciones a los golpes*: `Cabeza_Derecha/Izquierda`, `Cuerpo_Derecha/Izquierda` per distinct guard, i.e. Glass Joe, Bald Bull, Soda, in `<Name>/Animations/Generadas/`, plus one shared looping `Victoria`). With all muscles at zero Bald Bull's head points at the ceiling, so `PoseDePie` takes the head from the guard clip; when regenerating, the reference guard must come from the prefab's controller, not the scene's.
- **Rounds (RF-10, RF-11):** `ControlRondas` (own GameObject in each fight, with a child `Campana` holding the 3D bell source in a ring corner) runs `Preparacion` → `Round` → `Descanso` → ... → `Terminado`: 3 rounds of 90 s, 20 s rest, 5 s before the first bell. One bell strike opens a round and three close it. The clock uses scaled time, so pauses stop it, and it doesn't advance while the player is down. A round that reaches zero waits while `CuentaEnMarcha` (a `Func<bool>` that `Arbitro` sets) returns true. In each rest the opponent gets up, walks to his corner (the red one, `LimiteRing.EsquinaRoja`; facing where he walks, then turning to the player), drops his guard and can dodge again, and the player regains `fraccionSaludDescanso` of max health; his falls are not reset. Two clapper hits (`avisoDiezSegundos`) sound with ten seconds left. Outside rounds `AtaqueOponente` is paused (`Pausar`/`Reanudar`) and `Oponente.Protegido` makes punches not count. A KO ends the fight at once; otherwise **the judges decide** (10-point must): per round each of three judges gives 10 to whoever took more health off the other (as a fraction of max; only health lost during the round counts) and 9 to the other, 10-10 within `margenRoundParejo`, minus one per knockdown suffered; the judges differ by `sesgoJueces` (−2 %, 0, +2 %), so `Decision` can be "unánime", "mayoritaria", "dividida" or "empate". Whoever has more judges wins and **a tie goes to the player**. The enum still says `VictoriaPorSalud` / `DerrotaPorSalud` (kept for the saved logs and `Tools/tabla_heart.py`); `Tarjetas` / `TarjetasTexto` expose the cards (player's points first), shown on the victory and defeat signs and in `Scene_Results`. The course report still states the old health rule (RF-11). The result is raised in `AlTerminarCombate(ResultadoCombate)`. `MarcadorRing` (root object in each fight, *Tools > Boxeo > Poner reglamento*) shows round, clock and names on four TMP panels hanging from the lighting truss: scenery, not a HUD.
- **Referee (RF-12, RF-16):** `Arbitro` (own GameObject in each fight; its child `Cuerpo` holds the body, the 3D `AudioSource` `Voz` at head height and `CartelPulsar`) counts aloud from 1 to 10 with the clips in `numeros` (`Audio/Efectos/Voz_Cuenta_01..10.wav`; overwrite the WAVs or drag other clips to use recordings). For the player it only adds the voice: the time and the mashing stay in `RecuperacionJugador`, and the numbers split `segundosParaLevantarse`. For the rival it runs the count itself in a knockdown (the final fall isn't counted: three-knockdown rule) at `segundosPorNumero`. `cuentaKnockdown` in the profile is the number at which he is already **on his feet** (Glass Joe 9, Bald Bull 8, Soda 8, Sandman 7, Tyson 6; clamped to 9, since 10 is a knockout): `Levantarse` is called `segundosParaIncorporarse` (2 s) earlier, the count goes on to at least `cuentaProteccion` (8, the mandatory eight count) and only then the order "¡Box!" resumes the fight; from getting up until that order the rival is `Protegido` and `AtaqueOponente` is paused. Before the first number, once the rival is lying down (`ReaccionAnimada.EnElPiso`, at most `esperaMaximaCaida`), the referee orders "¡Esquina!" (the player to the neutral corner) and waits `pausaAntesDeContar` (1.3 s), while `CuentaEnMarcha` already holds the round. `AlOrdenar(OrdenArbitro, Vector3)` fires for `Box` (also `retrasoBox` after each round's bell and when the player beats the count), `Esquina` and `Fin` ("¡Nocaut!", on a KO either way); the voice clips are `Voz_Orden_Box/Esquina/Nocaut.wav`. While `Arbitro` is enabled it sets `Oponente.LevantaArbitro`, which turns off the `segundosKnockdown` timer; without it the rival gets up on that timer. An external `Levantarse` cancels the count and silences the voice. The count stops at `timeScale` 0, and the voice is paused by hand because an `AudioSource` ignores `timeScale`. If both are down (tests only), the player's count has the voice and the rival's keeps running silently. `Arbitro.AlDecirNumero` fires with each number. `CuerpoArbitro` (on `Cuerpo`) moves the visible referee: during the round 2 m to the side of the player–rival line, for the rival's count next to the rival on the player's side, for the player's count 1.05 m ahead of the player and 0.4 m aside (it picks the side that stays inside the ring), in the centre between both (1.05 m aside) during the preparation and the last 4 s of each rest, back to its start spot for the rest of the rest, and it stays where it is once the fight is over. Signals, all procedural arm poses blended in by weight in `LateUpdate`: "¡Box!" reuses the counting arm (raise, chop, lower), `Esquina` points an extended arm at the neutral corner while facing the player, `Fin` waves both arms overhead, and after any ending it points at the winner until the scene changes; never closer than 0.6 m to either fighter, clamped with `LimiteRing.DentroDelRing`. It moves with `SmoothDamp` (accelerates and brakes) and its feet step via `PasosProcedurales`; it raises the counting arm once the count has started and chops it down with each number, and shows the world-space sign "¡ARRIBA! PULSA A B X Y" only during the player's count. `Cuerpo > Modelo` is `Art/Characters/Referee/Referee.fbx` (Humanoid, no colliders) with `Animations/Referee.controller`: a 1D blend tree on the float `Agachado` between `Referee_DePie.anim` (0, a standing pose generated in muscle space from the FBX's `TPose`, breathing) and the FBX's crouched `Pose_Referee` (1); `CuerpoArbitro` drives it to 0.55 in rounds, 0.3 in the rival's count and 0 otherwise. With a humanoid `Animator` and `brazoCuenta` empty, the counting gesture rotates the avatar's right upper arm and forearm in `LateUpdate`, over the animation, blended in by weight: the shoulder angle is a damped spring (fast chop with a small overshoot, slower rise; `segundosAbajo` is how long it stays down), the forearm follows with its own spring (whip, elbow bent ~25° up, never hyperextended), and chest and head nod 5°/7° with each number; `brazoCuenta` (rotates on local X) is only for skeleton-less models. `Contar`/`Contando`/`Agachado` are sent only if the controller has them. *Tools > Boxeo > Montar réferi* creates the pose and controller if missing and mounts (or swaps) the model in the open scene. The FBX in use is decimated from ~379k to 20k triangles by `Tools/reducir_referi.py` (Blender, decimate before the armature modifier, keeps weights/UV); the untouched original is in `Referee/Source~/` (not imported). Its two clips are single-frame takes, so `clipAnimations` sets the take's frame range explicitly (the default 0–0 imports empty clips).
- **Level flow:** `ControlCombate` (own GameObject in each fight) listens to `ControlRondas` (without one in the scene, it wins when the `Oponente` is `Derrotado`), shows a "¡VICTORIA!" panel built in code on the camera, and loads `escenaResultados` (`Scene_Results`); only if that field is empty does it load `siguienteEscena` directly (Level 5's panel says "¡Eres el nuevo campeón!"). It stores the highest won level in `PlayerPrefs` `"nivelSuperado"`, which `MainMenu` reads to unlock levels (RF-09): level N opens once N-1 is won, and locked buttons show BLOQUEADO and don't load. `MainMenu`'s context menu can unlock everything or reset progress. Losing is handled by `RecuperacionJugador`, which after the K.O. or, through `PerderPorSalud`, the DERROTA sign loads its own `escenaResultados` (`Scene_Results`; `escenaAlPerder` is the fallback). The new fields take their defaults in the five fight scenes without re-saving them.
- **Results (RF-18, RF-19):** `PantallaResultados` (own GameObject in `Scene_Results`) gets nothing passed in: it reads `RegistroSesion.Instancia.CombateActual`, which was closed before the scene change and survives it, and shows title (¡VICTORIA!, DERROTA or ¡CAMPEÓN!), how the fight ended, precision (`precision`, landed of thrown), blocked attacks (`ataquesBloqueados` of `ataquesRecibidos`), total time (`segundosCombate`) and a detail line, on the menu's World Space Canvas (`OVRRaycaster`, `OVRInputModule`, `LaserCursor`, Bangers). Main button: SIGUIENTE NIVEL (`MainMenu.Levels[nivel]`) after winning levels 1–4, REINTENTAR (the fight's scene) after losing, REPETIR after winning level 5; the other is MENÚ (centred alone when there is no fight). A win plays `Multitud_Ovacion.wav` once. Winning the last level activates the belt, moves the Canvas 0.45 m right, turns it 15° and scales it to 80 %, and the subtitle becomes the closing text `textoCampeon`. The belt (`Art/CinturonCampeon/`) is the team's own, built by `Tools/crear_cinturon.py` (Blender headless; 1 540 triangles, no UVs or textures, three Standard materials remapped by name, axis conversion baked into the mesh): `CinturonCampeon` rises 0.6 m growing from 20 % with a small overshoot, spins at 35 °/s and pulses the gold's emission through a `MaterialPropertyBlock` (`Cinturon_Oro` keeps `_EMISSION` on with black emission for that), in unscaled time and with no light of its own.
- **Pause menu:** in the fight scenes, `PauseMenu` (on its own GameObject, not the Canvas, so hiding the Canvas doesn't disable it) toggles the Canvas and laser on `OVRInput.Button.Start` (left controller Menu button, key `M` in the Meta XR Simulator) and sets `Time.timeScale` to 0/1. On opening it moves the Canvas 1.5 m in front of the player's head (the player can walk around the ring), or closer (down to `minDistance`, 0.7 m) and scaled down in proportion when the rival or the referee stands in front nearer than that (otherwise the rival, ~1 m away, hid the menu and the Guardian warning); its graphics also get material copies with `unity_GUIZTestMode` = Always so it draws on top of everything (set with `SetFloat`: the UI shaders don't declare it and `SetInt` doesn't stick) and switches to the main panel. There, the Canvas title reads PAUSA and the buttons are rewired: `ButtonReanudar` → `PauseMenu.Hide`, `ButtonVolverMenu` → `PauseMenu.BackToMainMenu`. `PauseMenu.Show(string)` opens it with another title. `PausaGuardian` (next to `PauseMenu`, RF-20) pauses when the head leaves the Guardian's Play Area or the app loses input focus / the headset is removed, shows "VUELVE AL ÁREA SEGURA", and resumes only the pauses it opened. With OpenXR the Play Area comes in *Stage* space while the rig is *Floor Level* (origin where the headset started or was recentred): points centred on the origin are converted with `OVRPlugin.GetTrackingTransformRelativePose(Stage)` (this mismatch made the warning appear inside the area on the headset until 2026-11-13). The area is reloaded on focus regained, on recentre and every 2 s; it pauses after 0.25 s outside and resumes 5 cm further in; if the player presses REANUDAR while the game thinks they are outside, the geometry is discarded until the app closes (warning in the console). The geometry is never requested in the Editor. The Editor has no Guardian: use its context menus (*Probar: salir/volver al área segura*) or `simularAreaEnEditor`. `DebugLocomotion` (joystick move and snap turn, in the five fights) disables itself outside the Editor (RNF-04: only physical locomotion on the headset).
- **Menu input:** VR pointer interaction uses the Meta Core legacy UI stack (`OVRInputModule` + `OVRRaycaster` on the canvas; the input module accepts the right index trigger as well as A, which is what the simulator's Point + Click left mouse button sends). `LaserCursor` derives from `OVRCursor` and draws the ray with a `LineRenderer`, moving a dot to the hit point.
- **`MainMenu`** switches between the main, options and level panels (`MenuNiveles`, only in `Main_Scene`). JUGAR opens the level panel, whose buttons call `PlayLevel(1..5)` (scene names in `MainMenu.Levels`); the first four sit in a row and `ButtonNivel5` alone in a second row below them. Options has two 0–1 sliders wired to `SetVolume` and `SetHaptics`, initialised in `Awake` from `PlayerPrefs` `"volumen"` (applied to `AudioListener.volume`) and `"haptica"` (scales the vibration in `Puno` and `SaludJugador`).
- **Physics** runs at 72 Hz: *Fixed Timestep* is exactly 1/72 s (one step per Quest 2 frame, so an impact is detected at most one frame late; it was 0.02 s until block J). Only `Puno` uses `FixedUpdate`; it divides by the real time between steps (`fixedDeltaTime / timeScale`), because `EfectosGolpe` slows time down on knockdowns while the hands keep moving at real speed.
- **Hitting opponents:** `Puno` (kinematic, on each hand anchor) measures hand velocity relative to the `TrackingSpace`, so joystick locomotion and snap turns don't count as punches. Its smoothing `suavizado` is defined per 0.02 s and scaled to the real step, so the filter keeps the time constant it was calibrated with at 50 Hz. On `OnTriggerEnter` with a `ZonaGolpe` (trigger hitbox: `Cabeza` or `Torso`), it sends a `Golpe` to the `Oponente`; nothing lands while the player is knocked down. `Oponente` has health (`saludMaxima`): each hit deals the type's base damage, scaled by punch speed and ×`multiplicadorCabeza` on the head. He falls each time health crosses a threshold (with `caidasParaDerrota` = 3: at 66 %, 33 % and 0 %). The falls before the last are knockdowns and he gets up when `Arbitro` ends the count (`segundosKnockdown` without a referee), protected from hits for `segundosAlLevantarse` while the clip gets him up; the last one is the defeat (`Derrotado`), and he stays down until `Reiniciar()`. Hits don't count while he is down. `RecibirGolpe` returns a `ResultadoGolpe` (`NoCuenta`, `Conectado`, `Bloqueado`, `Esquivado`). `Oponente` raises the events `AlRecibirGolpe`, `AlBloquear`, `AlEsquivar`, `AlCaer`, `AlLevantarse` and `AlCambiarSalud`, and these components react to them:
  - `DefensaOponente` (RF-07) decides which punches he blocks: the profile's `probabilidadBloqueo`, rising by `bloqueoPorGolpeSeguido` per consecutive hit up to `bloqueoMaximo`. A block keeps the guard up for `segundosGuardia` (blocks everything, punching more doesn't extend it), then he is open for `aberturaTrasGuardia` and can't block. He never blocks while attacking. A blocked punch deals ×`danoTrasBloqueo`, never knocks him down and fires `AlBloquear` instead of `AlRecibirGolpe` (no reaction animation). The guard is shown with hand IK (Humanoid only): `DefensaOponente` adds a `RelevoIK` to the Animator object because `OnAnimatorIK` only reaches that object, and the base layer of `GlassJoe.controller` has IK Pass on (the override controllers inherit it). With `PerfilOponente.guardiaGrabada` set, the gloves follow that recorded trajectory (forward when raising, backward when lowering), starting from the animated hand pose (`GetIKPosition` at weight 0) and blending that offset out along the way, scaled by the rival's head height over the recorder's; without it they go straight to the fixed `posicionGuantes`. Recordings (`GrabacionGuardia` assets in `Data/Guardias/`) come from `GrabadoraGuardia` on the `OVRCameraRig` of `Main_Scene`: both thumbsticks pressed (or its context menu) → haptic countdown, 2 s of both hands relative to the head's yaw-only frame, trimmed to the raise, saved as JSON in `persistentDataPath/Guardias` and, in the Editor, as an asset. *Tools > Boxeo > Importar guardias grabadas* imports JSON pulled from the Quest. All four profiles use `Guardia_Provisional` (synthesized without a headset, *Tools > Boxeo > Crear guardia provisional*) until a real one is recorded. Hand rotations are recorded but not applied yet. Without a headset `OVRCameraRig` rewrites the hand anchors before rendering even when disabled, so the recorder accepts its own head/hand/floor transforms for tests.
  - `EsquiveOponente` (RF-07) decides at contact, before the block, so a feint doesn't trigger it: `probabilidadEsquive` (0 = never, the default), then `enfriamientoEsquive`. It doesn't dodge while attacking, down, getting up, `Protegido`, or with the guard up or just dropped (`DefensaOponente.GuardiaOcupada`). A dodged punch deals no damage, isn't a consecutive hit for `DefensaOponente`, gives no impact vibration and fires `AlEsquivar`, to which `AtaqueOponente` answers with `ventanaContraataque`. With no dodge clip yet it moves the transform by `distanciaEsquive`, away from the glove or backward, and comes back: the offset is applied as a per-frame delta, so it adds to `Acercarse` (which waits for it) and the walk home in the rest, and leaves no drift. Hitboxes follow because they hang from the bones, and `LimiteRing.DentroDelRing` keeps him inside the ropes.
  - `ReaccionAnimada` drives an Animator by state name. Uppercut to the head → `Uppercut_Face`; a punch whose velocity is at least `umbralLateral` (0.5) sideways in the rival's local space → `Cabeza_Derecha` / `Cabeza_Izquierda` on the head or `Cuerpo_Derecha` / `Cuerpo_Izquierda` on the torso ("Derecha" = it pushes him to his right; generated clips, see `Maniqui`); straight to the head → `Jab`; other torso hits → `Uppercut_Stomach`; then `Knockdown` / `Defeat`. `EsReaccion(hash)` lists the reaction states. When the rival wins the fight it plays the looping `Victoria` state `esperaCelebracion` (0.5 s) later. The controller's exit-time transitions bring the reactions and `Knockdown` back to `Idle`. The `Knockdown` clip falls, stays down and gets up in 3.7 s, so with a referee `ReaccionAnimada` holds it at `momentoPiso` until the count ends and then lets it continue.
  - `CuerpoVivo` (on the Animator object of the five rivals and of the menu's decoration boxers) is a procedural layer added on top of the clips in `LateUpdate`, after animation and IK: the head follows the player's eyes (`SetLookAtPosition`, so it needs IK Pass; it yields during reaction clips and switches off on the floor), every hit that lands shakes head or torso along the real direction of the fist (two damped springs; the axis is lever arm × punch direction, the amplitude follows `Golpe.intensidad`; a blocked hit gives 30 %), the torso leans toward where he dodges (`EsquiveOponente.Desplazamiento`), and as health drops he hunches, lowers his head and pants; when less than `margenTocado` (13 % of max health) is left before the next knockdown (`Oponente.MargenHastaCaida`) he looks hurt: he sways, his head hangs and his forearms drop (the forearms only in `Idle`, not while attacking or guarding), the HUD-less cue that he is about to go down. It changes no clip and no combat rule. Without an `Oponente` (menu) it only looks and breathes, and offsets its `Idle` so characters sharing a clip don't move in sync.
  - `EfectosGolpe` (next to `Oponente`) emits a sweat splash at the contact point along the punch direction (one `ParticleSystem` built at start, at most 96 particles, material `Art/Efectos/Particula_Suave.mat`), a pale puff on a block, and a short slow motion on each fall (`timeScale` 0.45 for 0.45 s real on a knockdown, 0.28 for 1.1 s on the final one; it lets go if anyone else changes the time, e.g. the pause, and can be turned off with `camaraLenta`).
  - `ReaccionProcedural` is for the remaining `.glb` characters, which have no skeleton: it leans and pushes the model from the feet with a spring.
  - `AtaqueOponente` makes him turn toward the player (`Camera.main` by default) and attack from `Idle` every `intervaloAtaque` seconds. With an empty `combo` in the profile, every `uppercutCada`-th attack is `Ataque_Uppercut` and the rest are `Ataque_Jab`. With a `combo` (a `TipoAtaque[]`), each attack chains those punches without going through `Idle`, starting the next one `segundosEntreGolpesCombo` after each impact; each punch aims at the head again. A connected hit, a fall, the player going down, `Pausar` or disabling the component cancel the rest of the combo and any pending impact; a punch the player blocks doesn't. `Atacando` stays true between combo punches, so he neither blocks nor dodges there. Each hit he takes resets the wait to `esperaTrasGolpe`. A reaction started mid-attack cuts the attack off, and he doesn't attack while down or while the player is down. Nor does he launch while the player's head is farther than `alcanceAtaque` from `alturaAtaque` (the impact geometry): he keeps walking in and attacks as soon as he arrives. When an attack starts it aims at the player's head; `retardoImpacto*` seconds later (the moment the fist lands in the clip, divided by `velocidadAtaque`, which also sets `Animator.speed` during the attack) it calls `SaludJugador.RecibirAtaque` along a line from `alturaAtaque` up to `alcanceAtaque` m. Reactive behaviour: from `Idle` he walks toward the player at `velocidadDesplazamiento` until `distanciaCombate`, clamped to `LimiteRing.AreaRing`, and once at fighting distance he circles sideways around the player at `velocidadLateral`, picking a direction (or standing still) every few seconds and staying within `arcoLateral` (35°) of the initial player–rival line, so the player only has to turn a little (`MoverPies`); each hit pushes him back `retrocesoPorGolpe` metres and a critically damped spring brings him back in ~0.4 s (applied as a per-frame delta, like the dodge: a push that only decayed made him drift out of arm's reach under a flurry, since he only walks in `Idle`); when he knocks the player down he backs off to the neutral corner farthest from the player (`LimiteRing.EsquinaNeutralLejana`, `separacionEsquina` from the ropes, at `prisaEsquina` × his walking speed) and there plays the `Burla` state once (`probabilidadBurla`, 0 for Glass Joe); each attack plays one of the profile's `sonidosAtaque` (an exhale) before the impact; while the player's guard is down (`SaludJugador.EnGuardia`) the wait runs ×(1 + `castigoGuardiaBaja`) faster; after a block he counterattacks after `contraataqueTrasBloqueo`.

  Per-character values (name shown to the player, health, damage, defence, speed, timings, sounds) live in a `PerfilOponente` asset (difficulty rises Glass Joe < Bald Bull < Soda Popinski < Mr. Sandman < Iron Mike Tyson, RF-08; `python3 Tools/modelo_dificultad.py` estimates each rival's damage per second and the punches needed to beat him, and `docs/Entrega5.md` explains the simulated fight used to compare them) (`Assets/_Project/Data/Oponentes/`). *Tools > Boxeo > Configurar oponente seleccionado* sets up a character (select the root that holds the Animator, e.g. the FBX/prefab instance). With a Humanoid Animator, it adds `ReaccionAnimada` and `DefensaOponente` (turning on IK Pass in the base controller) and builds each hitbox from the vertices skinned to the head and the spine bones, parented to those bones so the hitboxes follow the animation. Without one, it uses heights. It also adds `EsquiveOponente`, inert while the profile's probability is 0. It does not add `AtaqueOponente`. Adjust the hitboxes by eye afterwards. *Tools > Boxeo > Poner pulido de combate* adds `CuerpoVivo` and `EfectosGolpe` in every build scene, assigns the particle material and the whoosh clips, writes the footwork values and attack sounds into the five profiles and creates the `Burla` state; it can be re-run. `docs/Pulido_Entrega_Final.md` describes this final polish pass (branch `entrega-final/pulido-combate`; its second half is the 2026-11-14 pass: menu poses, arena, lateral reactions, boxing rules, referee signals) and what still has to be checked on the headset. *Tools > Boxeo > Poner reglamento* (`ReglamentoBuilder`) assigns the order and clapper clips, builds `MarcadorRing` and writes `cuentaKnockdown` into the five profiles.
- **Player:** on the `OVRCameraRig`. `SaludJugador` resolves each attack as dodged (head off the punch line), blocked (both hands in guard in front of the face, takes `danoTrasBloqueo`) or hit. At 0 health, `RecuperacionJugador` starts a 10 s count in which mashing A/B/X/Y gets the player up; `saludPorCaida` sets how many times and with how much health, and running out loses by K.O. The count has no panel: `Arbitro` says it, and only the final K.O. and DERROTA signs are shown on the camera. `FeedbackSalud` is the diegetic feedback (vignette, heartbeat; the clip must be a single short beat, `Audio/Efectos/Latido.wav`). During the count it follows `Progreso` instead of health: the view clears and the heartbeat calms with each press, and each press vibrates harder (`AlPulsar`). Hits taken and blocked sound in 3D at the impact point (`SaludJugador` sound fields). `LimiteRing` keeps the head inside the ropes and out of the opponent (`distanciaMinima`). `DebugSalud` (health bars in a world-fixed panel to the player's left, hidden at start, toggled with the Y button: `OVRInput.RawButton.Y`; until 2026-11-13 it read `Button.Four` on `LTouch`, which maps to no button, so the bars could never be shown) and `PruebaAtaques` are test-only and the course report asks for no HUD (RF-14).
- **Session log (RF-21):** `RegistroSesion` creates itself at startup (`RuntimeInitializeOnLoadMethod`, `DontDestroyOnLoad`), so no scene holds it. In each scene with an `Oponente` it listens to existing events (no gameplay changes) and records per fight: level, rival, retry, result (or `Abandonado` when the scene is left early), round, fight seconds, punches thrown (`Puno.AlLanzarGolpe`: hand moving away from the head faster than 1.5 m/s, or touching the rival), landed by type, blocked and dodged by the rival, precision and effectiveness, attacks received/blocked/dodged, falls, counts survived, final health, vibrations and FPS during rounds, and the haptic latency (RNF-02): mean, p95 and max of the code latency (from `Puno.OnTriggerEnter`, which stamps `Haptica.Ahora()`, to the return of `OVRInput.SetControllerVibration`, published by `Haptica.AlMedirLatencia` for the first pulse of each punch's pattern) and of the estimated detection delay (`Puno.AlEstimarRetrasoDeteccion`: penetration depth into the hitbox over entry speed, i.e. what the physics step lost), plus `pasoFisicaMs`, and for RNF-03 `segundosHastaGuardia` (first time both hands are held in the blocking position, `SaludJugador.EnGuardia`, for 0.5 s; the value is when they went up) and `segundosHastaGolpeConectado` (first connected punch), in scaled time from the fight's first bell, −1 if it didn't happen; `DatosSesion` has the same two fields in fight time accumulated from the session's first bell (earlier fights count from their bell to their end). The runtime/controller part of the latency can't be measured from code. New fields and CSV columns always go at the end; an older `combates.csv` only gets its header line extended. It writes `persistentDataPath/Sesiones/sesion_<id>.json` (rewritten after each fight, on scene exit, pause and quit) and appends to `combates.csv`. `ControlCombate.Nivel` exposes the level. The latest fields, at the end as always, are `tarjetas` (the judges' cards, "29-28 29-28 28-29") and `decision`. `CombateActual` keeps the last (closed) fight until another starts, which is what `Scene_Results` shows. Examples in `docs/ejemplos/`.
- **Audio (RF-16):** `Assets/_Project/Audio/Efectos/` holds punches, block, hit taken, heartbeat, crowd, bell and the referee's numbers (a formant synthesizer), synthesized by `Tools/sintetizar_audio.py` (stdlib-only Python, fixed seeds; run `python3 Tools/sintetizar_audio.py Assets/_Project/Audio/Efectos` to regenerate; this also overwrites recordings placed over the `Voz_Cuenta` clips). It also takes name prefixes (`... Efectos Golpe_Aire Rival_`) to write only those sounds. `Golpe_Aire_1..3` is the glove's whoosh, played by `Puno` (`sonidosAire`) when a punch is thrown, `Rival_Esfuerzo_1..3` the rival's exhale when he attacks, `Voz_Orden_Box/Esquina/Nocaut` the referee's orders (same phonemes as the numbers, table `ORDENES`) and `Aviso_Diez_Segundos` the ten-second clapper; connected hits are louder the harder the punch, with a slightly random pitch (`Oponente.Sonar`). `AmbienteMultitud` (object `Multitud` at the ring centre in each fight) loops the murmur from several 3D sources around the ring and cheers from the nearest ones when the opponent or the player falls, raising `_PublicoAnimo` for `segundosAnimado` so the visible crowd jumps. The opponent's `AudioSource` and the referee's voice are 3D.
- **Procedural steps:** there are no walk clips. `PasosProcedurales` (on the Animator object of the five rivals, only in `Idle`, and of the referee, always; added by *Tools > Boxeo > Poner pasos procedurales*, which also turned on IK Pass in `Referee.controller`) pins each foot with foot IK only while the body moves or turns (> 0.12 m/s or 25 °/s) and steps it in an arc to its stance spot when the body is 0.12 m / 30° away, alternating feet (both at once on a sudden move such as a dodge); above 0.35 m/s the stride lengthens and lifts with speed (`zancada`, up to ×1.5 at 1 m/s), for the walks to the corners and the referee crossing the ring; when still it settles the feet and hands back to the animation. The stance is read from the bones in `LateUpdate` while IK is off: inside `OnAnimatorIK`, `GetIKPosition` returns the previous frame's goal, not the animated pose, even at weight 0 (reading it made the feet climb 48 cm over ~30 steps). The IK goal of a foot is not the bone: its rotation and position differ by a rig-specific offset (near zero on Mixamo rigs; on Mr. Sandman's, passing the bone rotation flipped the foot), so that offset is measured while IK is off and the body is still, and added when pinning. With `ApoyoEnSuelo` the stance is stored without that component's hip lift, so the feet are pinned at clip height and `ApoyoEnSuelo` lifts them as usual (stored lifted, it saw no sunk soles and Sandman stepped crouched by 24 cm).

- **Punch types:** `Golpe.Clasificar` sorts each hit by the hand's direction relative to where the head faces, with a fixed orthodox stance. Mostly upward is `Uppercut`; straight forward is `Jab` with the left hand and `Cross` with the right; anything else is `Lateral` (hooks). Each type has its own base damage in the profile; Lateral gets a soft vibration. Each type has its own vibration pattern in `Puno`, scaled by the `"haptica"` setting; a punch the opponent blocks gets a dull low-frequency double tap (RF-15), one he dodges a faint 30 ms brush, and one that knocks him down three strong pulses. During the player's count `FeedbackSalud` adds a tick per number on both controllers (0.2 → 0.6). All combat vibration goes through the static `Haptica` (`Fijar`/`Apagar`), which raises `AlVibrar` so tests and the session log can observe it; only `MainMenu`'s slider preview calls `OVRInput` directly. The procedural reaction's `intensidad` saturates at `rapidezGolpeCompleto` (2.5 m/s), so punching harder doesn't add anything. `Oponente` logs every hit to the console (`registrarGolpes`).

## Repository conventions

- Large binaries (png, fbx, wav, zip, dll, …) are tracked with **Git LFS** via `.gitattributes`. On a new machine install Git LFS (`winget install GitHub.GitLFS` on Windows) and run `git lfs install` before cloning, or `git lfs pull` afterwards. Without it the clone contains only text pointers and the arena (textures, meshes) shows up broken or empty; if Unity was already opened, delete `Library/` and reopen.
- Meta Avatars SDK, the multiplayer packages (Netcode, Lobby, Multiplayer Services), Visual Scripting and Timeline were removed on purpose as unused. Don't reintroduce them without a reason. Stale `Oculus.AvatarSDK2*.csproj` files at the root are generated and git-ignored.
- The Meta Project Setup Tool items about the Platform SDK (Data Use Checkup, application ID) don't apply, because the game doesn't use the Platform SDK.
- `docs/informe/` holds the course report: the LaTeX sources and PDF of week 13 (the PDF is not rebuilt on every change), the week 14 draft `Informe_SimuladorBox_Semana_14.tex` (own copies `secciones/*_s14.tex` of the sections that changed, plus `s12_entregable5.tex`; data still missing from the headset or users is marked `\pendiente{...}` in red and the cover counts them: don't commit its PDF while any remain; compile with `latexmk -xelatex -outdir=<scratch>` to keep `.aux` files out of the repo) and `Informe_SimuladorBox_Semana_12.pdf`, the PDF delivered in week 12 (deliverable 4). That one is the grader's annotated download: same pages, plus two hidden teacher notes (pp. 7 and 13). The PDFs are in plain git, not LFS.
